\chapter[ANÁLISIS Y DISEÑO]{Análisis y diseño}
\label{cap:analisis-diseno}

El análisis consiste en identificar qué debe ocurrir dentro del sistema y cómo se relacionarán
entre sí los distintos procesos que lo conforman, lo que permite entender el problema y documentar
las relaciones entre los usuarios, el programa y los componentes que integran la lógica del
sistema antes de escribir cualquier línea de código \cite{pressman2010}. En el caso del presente
trabajo, esta etapa corresponde a las fases de definición de requerimientos y de diseño de la
arquitectura del modelo incremental descrito en el Capítulo~\ref{cap:propuesta}, y se orienta a
describir, mediante requerimientos y diagramas, el comportamiento esperado de la interfaz del P300
Speller, de la adquisición y calibración con el casco EEG, del módulo de detección de la
componente P300 y del módulo de predicción de palabras,
combinando el lenguaje del usuario con el enfoque técnico de quien desarrolla el sistema.

Por otra parte, el diseño se encarga de traducir dicho análisis en decisiones concretas de
implementación: a partir de los requerimientos y los diagramas generados se define cómo se
organizará el código en módulos, cómo se intercambiará la información entre la interfaz, el
modelo de aprendizaje profundo y el modelo de lenguaje, qué datos deberán almacenarse, así como la
plataforma en la que se ejecutará cada componente y los recursos que requerirá \cite{pressman2010}.

\section[REQUERIMIENTOS]{Requerimientos}

Los requerimientos establecen lo que el sistema debe hacer, en el caso de los funcionales, y las
condiciones de plataforma, calidad y documentación bajo las que debe hacerlo, en el caso de los no
funcionales \cite{pressman2010}. Cabe señalar que el entrenamiento del modelo de cada usuario y su evaluación mediante

por parte de quienes desarrollan el sistema, como se describe en la
Sección~\ref{sec:flujo-entrenamiento}, por lo que no forman parte de lo que la aplicación ofrece a
la persona que la utiliza.

\subsection{Requerimientos funcionales}

\begin{itemize}
  \item \textbf{RF1:} El sistema deberá proveer una interfaz gráfica que muestre una matriz de
  selección de $5\times5$ posibles objetivos.
  \item \textbf{RF2:} El sistema deberá intensificar de manera aleatoria las filas y columnas de la
  matriz durante cada secuencia de estimulación.
  \item \textbf{RF3:} El sistema deberá efectuar el preprocesamiento de las señales EEG.
  \item \textbf{RF4:} El sistema utilizará el modelo de aprendizaje profundo del usuario para clasificar cada
  época como objetivo o no objetivo, asignándole un puntaje de probabilidad.
  \item \textbf{RF5:} El sistema deberá determinar el carácter seleccionado a partir de la
  acumulación de los puntajes de cada fila y cada columna a lo largo de las repeticiones.
  \item \textbf{RF6:} El sistema mostrará en la interfaz el texto construido por el usuario,
  actualizándolo después de cada selección.
  \item \textbf{RF7:} El sistema contará con un módulo de predicción de palabras que genere
  sugerencias a partir de los caracteres escritos hasta ese momento.
  \item \textbf{RF8:} El sistema permitirá seleccionar una palabra sugerida mediante el mismo
  mecanismo de estimulación y detección de la componente P300.
  \item \textbf{RF9:} El sistema permitirá borrar el último carácter o palabra seleccionados
  mediante un objetivo de la matriz.
  %% PROPUESTA nueva: sesiones de usuario (la herramienta podrá ser usada por más de una persona)
  \item \textbf{RF10:} El sistema permitirá crear una cuenta de usuario.
  \item \textbf{RF11:} El sistema permitirá iniciar sesión con una cuenta existente, de modo que
  cada usuario acceda a su propia sesión.
  \item \textbf{RF12:} El sistema permitirá cerrar la sesión activa.
  \item \textbf{RF13:} El sistema guardará los mensajes construidos en la sesión del usuario y le
  permitirá consultarlos posteriormente.
  %% PROPUESTA nueva: adquisición de señales propias y calibración por usuario
  \item \textbf{RF14:} El sistema deberá conectarse al casco EEG y recibir en tiempo real las
  señales de sus canales, sincronizadas con los estímulos presentados.
  \item \textbf{RF15:} El sistema permitirá verificar la calidad de la señal de los canales antes
  de iniciar una calibración o una sesión de deletreo.
  \item \textbf{RF16:} El sistema contará con un modo de calibración en el que se indique al
  usuario el carácter en el que debe fijar su atención, se presenten las secuencias de estimulación
  y se registren las señales correspondientes.
  \item \textbf{RF17:} El sistema guardará los registros de cada sesión de calibración en la cuenta
  del usuario que los generó.
  \item \textbf{RF18:} El sistema cargará, al iniciar sesión, el modelo de detección entrenado para
  ese usuario y no permitirá iniciar el deletreo si la cuenta aún no cuenta con uno.
\end{itemize}

\subsection{Requerimientos no funcionales}

\begin{itemize}
  \item \textbf{RNF1:} El sistema deberá implementarse en el lenguaje de programación Python.
  \item \textbf{RNF2:} El sistema deberá ejecutarse en una computadora con sistema operativo
  Windows (PENDIENTE DE DEFINIR CON JETSON).
  \item \textbf{RNF3:} La presentación de los estímulos deberá sincronizarse con los instantes
  registrados de cada intensificación, de modo que cada época corresponda al estímulo que la
  provocó.
  \item \textbf{RNF4:} La clasificación de las épocas de una selección deberá completarse en un
  tiempo que no retrase de manera perceptible la presentación de la siguiente secuencia de
  estímulos.
  \item \textbf{RNF5:} La interfaz deberá presentar la matriz con un tamaño de carácter y un
  contraste suficientes para que el usuario pueda fijar su atención sin esfuerzo visual excesivo.
  \item \textbf{RNF6:} El sistema deberá tener una arquitectura modular que permita reemplazar el
  modelo de detección o el modelo de predicción de palabras sin modificar la interfaz.
  \item \textbf{RNF7:} La etapa de inferencia del modelo deberá poder evaluarse en un
  microordenador NVIDIA Jetson.
  \item \textbf{RNF8:} El código fuente deberá estar documentado y acompañarse de un manual de
  usuario que describa la instalación, la ejecución y el uso general del sistema.
  %% PROPUESTA nueva: derivada de las cuentas de usuario
  \item \textbf{RNF9:} Las credenciales de los usuarios deberán almacenarse de forma protegida, sin
  guardar las contraseñas en texto plano, y los mensajes y registros EEG de cada usuario solo deberán ser accesibles
  desde su propia sesión y por el operador.
  \item \textbf{RNF10:} El sistema deberá ser compatible con el casco EEG de 14 canales
  seleccionado y con la frecuencia de muestreo con la que este entrega las señales (PENDIENTE DE
  CONFIRMAR EL MODELO DEL CASCO).
\end{itemize}

El catálogo de mensajes reúne los avisos que el sistema presenta durante su operación, clasificados
según su propósito para que la interfaz mantenga un lenguaje uniforme en todas sus pantallas. Dado

proporcionados no son válidos, como al registrar una cuenta o iniciar sesión, o porque un recurso
necesario no está disponible, como el modelo de detección o la conexión con el casco EEG.

\section[ARQUITECTURA DE SOFTWARE]{Arquitectura de software}

La arquitectura presentada en la Figura~\ref{fig:arquitectura} del Capítulo~\ref{cap:propuesta}
describe las etapas por las que transita la señal, desde su adquisición hasta la construcción del
texto, mientras que la arquitectura de software describe cómo se organiza el código que realiza
dichas etapas y de qué manera se comunican los componentes entre sí. Para ello se propone una
división en tres capas: la capa de presentación, desarrollada con PyQt, que contiene la matriz del
P300 Speller, el área del texto, las sugerencias y las pantallas de registro, inicio de sesión y calibración, luego la
capa de lógica, que agrupa el control de la sesión de deletreo y de calibración, la adquisición de las señales, la
generación de estímulos, el
preprocesamiento, la detección de la componente P300, la decodificación del carácter y la
predicción de palabras, y por último la capa de datos, responsable de las cuentas de usuario, los mensajes
guardados, los registros EEG de calibración y el modelo entrenado de cada usuario. Esta separación responde al requerimiento de
modularidad, ya que permite sustituir el modelo de detección o el de predicción de palabras sin
modificar la interfaz.

\section[DIAGRAMAS DE FLUJO]{Diagramas de flujo}

Los diagramas de flujo describen la secuencia de pasos de los procesos más importantes del sistema,
y se presentan aquí los tres que concentran la lógica del procesamiento de las señales y del
modelo: el preprocesamiento, el entrenamiento del modelo de detección y la decodificación del
carácter seleccionado.

\subsection{Preprocesamiento de las señales EEG}

El preprocesamiento aplica a las señales las técnicas descritas en la Sección~\ref{sec:pds}, entre
ellas el filtrado pasa banda, el remuestreo, la segmentación en épocas posteriores a cada estímulo
y la normalización de cada canal, y es común tanto al flujo de entrenamiento como al de uso del
sistema, de modo que el modelo recibe en ambos casos datos con el mismo formato, ya provengan de las bases de datos públicas o
del casco EEG. Los valores
específicos de cada parámetro se definirán durante el diseño experimental.

%% TODO: diagrama de flujo del preprocesamiento.

\subsection{Entrenamiento y evaluación del modelo de detección}
\label{sec:flujo-entrenamiento}

El entrenamiento y la evaluación del modelo de detección de la componente P300 se realizan antes y
fuera de la aplicación, por parte del operador, siguiendo las fases de la metodología CRISP-ML
descritas en el Capítulo~\ref{cap:propuesta}, y constan de dos etapas. En la primera, de
exploración, se preparan los datos de las bases públicas, se entrenan las arquitecturas candidatas y
se evalúa su desempeño con las métricas de clasificación revisadas en la
Sección~\ref{sec:metricas}, bajo esquemas de validación intrasujeto e intersujeto, así como el
efecto de reducir el número de canales y de repeticiones. En la segunda, el modelo seleccionado se
entrena o ajusta para cada usuario con los registros de su sesión de calibración, que se
preprocesan con el mismo flujo de la sección anterior, y se evalúa antes de entregarlo. Ninguno de
estos resultados se presenta a quien utiliza el sistema, que únicamente recibe como producto el
archivo con el modelo entrenado para su cuenta.

\subsection{Decodificación del carácter seleccionado}

La decodificación recorre las repeticiones de una selección: en cada una se intensifican las filas
y columnas de la matriz, se clasifican las épocas resultantes y se acumulan los puntajes por fila y
por columna, de acuerdo con la Ecuación~\eqref{eq:decodificacion}, hasta que se completa el número
de repeticiones y se elige el elemento ubicado en la intersección de la fila y la columna con el
puntaje más alto.
